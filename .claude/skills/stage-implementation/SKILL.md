# 단계 구현

테스트가 먼저 실패해야 그 테스트가 이번 단계의 없는 동작을 가리킨다. 처음부터 통과하는 테스트는 이미 있는 동작을 확인하므로 단계 완료의 증거가 되지 않는다.

## 시작 조건

`_workspace/04_client-liaison_confirmation.md`의 `status`가 `confirmed`이고, 이번 단계가 `_workspace/05_page-designer_stages.md`에 있을 때만 시작한다. 아니면 파일을 바꾸지 않고 반환한다.

한 호출에서는 아래 셋 중 리더가 지정한 하나만 한다.

## 1. 실패 테스트

- 이번 단계의 "실패해야 할 테스트가 증명할 것"만 테스트로 작성한다.
- 제품 동작은 구현하지 않는다.
- 테스트를 실행한다. 실패하면 `failed: true`와 실행한 명령을 반환한다.
- 통과하거나 실행하지 못하면 `failed: false`를 반환하고 구현을 시작하지 않는다.
- 기록을 `_workspace/06_page-implementer_stage-<id>.md`에 남긴다. 명령, 실패 요약, 아직 구현 전임을 적는다.

## 2. 구현

- 같은 파일의 테스트가 실패한 기록이 있을 때만 구현한다.
- 그 테스트를 통과시키는 데 필요한 만큼만 구현한다.
- 설계와 시각 명세에 없는 화면이나 기능을 추가하지 않는다.
- 테스트를 기대가 낮아지도록 수정하지 않는다.
- 이 호출에서는 커밋하지 않는다.

## 3. 커밋

- `_workspace/07_qa-inspector_stage-<id>.md`의 판정이 통과일 때만 커밋한다.
- 로컬 커밋만 한다. 푸시, 원격 설정, 인증 설정, 강제 이력 변경, 훅 무시는 하지 않는다.
- 메시지에는 단계 식별자, 단계 이름, 통과한 테스트 명령을 넣는다.

```bash
git commit -m "$(cat <<'EOF'
S1: 단계 이름

통과 테스트: 실행한 명령
EOF
)"
```

- 훅이 거절하면 원인을 고치고 새 커밋을 만든다. 방금 만든 커밋을 고쳐 다시 넣지 않는다.
- 비밀 값, 원본 서비스의 계정, 토큰이 들어 있는 파일은 커밋하지 않고 리더에게 알린다.
