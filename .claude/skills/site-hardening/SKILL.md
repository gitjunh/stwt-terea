# 성능·안전성·보안

최적화는 이미 통과한 단계의 동작을 유지한 채 위험을 줄이는 작업이다. 새 요구를 여기서 구현하면 컨펌된 범위가 커진다.

## 시작 조건

단계 목록의 모든 단계에 통과 QA 보고서가 있을 때만 시작한다. 실패한 단계가 있으면 고치지 않고 그 단계 번호를 리더에게 알린다.

## 검토 순서

세 축을 모두 기록한다. 손댈 필요가 없으면 이유를 적는다.

1. 성능: 같은 자원을 반복해서 받거나, 첫 화면에 필요 없는 큰 자원을 막는지 본다. 화면 문구와 순서를 바꾸지 않는다.
2. 안전성: 깨진 링크, 없는 자원, 오류 상태에서도 화면이 명세 안에 남는지 본다.
3. 보안: 비밀 값, 원본 서비스의 계정, 토큰, 신뢰할 수 없는 외부 스크립트, 입력의 무분별한 삽입을 제거한다. 원본에 로그인 화면이 있어도 실제 자격 증명을 복제하지 않는다.

기존 단계 테스트를 지우거나 기대를 낮추지 않는다. 수정 뒤에 그 테스트 명령을 다시 실행하고, 실패한 최적화는 유지하지 않는다.

## 출력

`_workspace/08_site-hardener_report.md`

```markdown
# 최적화
## 성능
- 변경 또는 유지 이유 / 파일

## 안전성
## 보안
## 다시 실행한 테스트
- 명령 / 결과
```
