# 상용 웹 검수

단계 테스트 통과와 코드 최적화만으로는 상용 출시 가능 여부를 보장하지 못한다. 이 스킬은 **요구 일치 · 상용 가능 · 보안·검증·안전성**을 한 번에 검수한다.

## 시작 조건

- 컨펌이 `confirmed`이고, 구현 단계 QA와(해당하면) hardening QA가 끝난 뒤가 기본이다.
- 클라이언트가 “상용 가능한지”, “요구대로인지 검수해 줘”라고 하면 그 시점의 사이트 경로로도 실행한다.

## 검수 축

1. **요구 일치** — `_workspace/01_client-liaison_requirements.md`의 확정 요구마다 구현·문서를 대조한다. `반영` / `부분` / `누락` / `미결(질문 대기)`.
2. **상용 가능** — 로컬 데모가 아닌 서비스로 볼 때: 인증·권한, 데이터 저장 지속성, 비밀 관리, 배포·재현 절차, 장애·오류 안내, 관리·방문 핵심 업무 완결성.
3. **보안·검증·안전성** — 하드코딩 비밀, 원본 운영 자격 증명, 권한 우회, 입력 검증 부재, XSS·무분별한 HTML 삽입, 안전하지 않은 외부 스크립트, 테스트 계정 노출 방식.
4. **원본·캡처 대비 기능 공백** — 사이드바·위저드·동의 게이트·다중 선택 등 클라이언트가 지적한 유형의 누락이 남아 있는지.

제품 코드는 수정하지 않는다. 쓸 파일은 검수 결과뿐이다.

## 출력

`_workspace/13_commercial-web-reviewer_verdict.md`

```markdown
# 상용 웹 검수
- status: pass | revise | block
- commercialReady: true | false
- 사이트 경로:
- 근거 요구·설계·QA 경로:

## 요구
- R#. 반영|부분|누락|미결 | 근거

## 상용 가능
- 항목 / 판정 / 근거

## 보안·검증·안전성
- 항목 / 판정 / 근거

## 반려
- 대상: page-implementer | site-hardener | page-designer | client-liaison
- 내용:
- 근거:

## 요약
- 한 줄
```

### status 규칙

| status | 의미 |
| --- | --- |
| `pass` | 확정 요구의 치명 누락 없음, 상용에 막는 보안·안전 이슈 없음. 미결 질문은 남아도 되나 `commercialReady`는 false일 수 있다. |
| `revise` | 구현·문서 수정으로 닫을 수 있는 부족. 리더가 해당 담당에게 되돌린다. |
| `block` | 상용 불가 수준의 보안·데이터·권한 문제, 또는 핵심 요구 대량 누락. |

`commercialReady: true`는 미결(SMS 키 등)이 상용 필수인데 열려 있으면 쓰지 않는다. 로컬·스테이징 데모만 가능하면 `false`와 이유를 적는다.
