# 호출 조건 점검

`homepage-orchestrator`를 불러야 하는 요청과, 표현은 비슷하지만 다른 스킬을 써야 하는 요청이다.

## 불러야 하는 요청

1. 이 URL이랑 샘플 마크다운으로 방문 페이지를 그대로 복제해 줘.
2. 홈페이지 클론 시작하자. 요구는 내가 이어서 말할게.
3. 방금 말한 버튼 문구도 요구에 반영해서 설계를 다시 잡아 줘.
4. 설계가 내가 말한 요구랑 맞는지 보고, 맞으면 컨펌 받을 문안을 줘.
5. 컨펌했으니 단계별로 구현해 줘.
6. 2단계만 다시 실행해 줘. 테스트가 요구랑 달랐어.
7. 이전 결과를 바탕으로 모바일에서 표가 깨지는 것만 보완해 줘.
8. 구현 업데이트해 줘. 원본에 있는 안내 문장이 빠졌어.
9. 모든 단계 끝났으면 보안이랑 성능만 다듬어 줘.
10. 단계별 구현 파일하고 코드 대응 문서 작성해 줘.

## 부르면 안 되는 요청

1. 하네스 구성을 점검해서 에이전트 정의가 스킬과 맞는지 봐 줘. — harness 스킬
2. 이번 복제 결과가 아쉬우니 하네스에 피드백을 반영해 줘. — evolve 스킬
3. 하네스 회고하고 스킬 설명을 고쳐 줘. — evolve 스킬
4. README에 있는 복제 원칙이 무슨 뜻인지 짧게 설명해 줘. — 단순 질문, 오케스트레이터 없이 답한다
5. 이 마크다운에서 URL만 찾아서 알려 줘. — 단순 조회
6. 샘플 문서의 오타를 고쳐 줘. — 원본 자료 수정이지 페이지 복제 흐름이 아니다
7. 깃 상태만 보여 줘. — 저장소 조회
8. 커밋 메시지 스타일을 예시로 알려 줘. — 일반 설명
9. 에이전트 팀을 새로 설계해 줘. — harness 스킬
10. 방문 페이지와 상관없는 정렬 함수를 작성해 줘. — 이 복제 작업의 요구·설계·구현이 아니다
