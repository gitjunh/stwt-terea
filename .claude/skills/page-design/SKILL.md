# 페이지 설계

설계는 구현자가 원본과 요구 중 무엇을 따라야 하는지 한곳에서 보게 하는 문서다. 원본에 없는 개선을 본문에 섞으면 검증이 확정된 변경인지 구분할 수 없다.

## 읽을 자료

1. `_workspace/01_client-liaison_requirements.md`
2. 요구에 적힌 관련 정보 마크다운. 페이지 제목, 레이아웃 주석, 이미지와 문구, 출처 URL을 화면 단위로 읽는다.
3. 반려가 있으면 `_workspace/03_design-reviewer_verdict.md`의 페이지 설계 항목만.

관련 정보 파일을 열 수 없으면 기억이나 샘플로 설계를 채우지 않는다.

## 설계 파일

`_workspace/02_page-designer_design.md`

```markdown
# 페이지 설계
- 대상 URL:
- 관련 정보:
- 요구 번호 범위:

## 원본과 문서의 차이
- 항목 / URL에서 확인한 내용 / 문서의 내용 / 채택 (URL 우선)

## 화면
### [화면 이름]
- 문구:
- 링크와 이동:
- 이미지:
- 사용자가 거치는 순서:
- 요구 번호:

## 확정된 개선
- 요구 번호 / 원본과 다른 점

## 제안
- 설계에 반영하지 않은 개선
```

- 요구에 없는 개선은 `확정된 개선`에 넣지 않는다.
- 문서에 있는 화면을 빼려면 요구 번호로 제외 근거를 적는다.

## 단계 목록

`_workspace/05_page-designer_stages.md`

한 단계는 한 화면의 한 동작이거나, 그보다 작은 확인 단위다.

```markdown
# 구현 단계
- 사이트 경로: sites/<식별자>/

## S1. [한 줄 이름]
- 확인할 동작:
- 실패해야 할 테스트가 증명할 것:
- 포함하지 않을 것:
```

테스트 코드는 쓰지 않는다. 아직 구현이 없어야 실패하는 기대만 적는다.
