# 설계 검증

검증 결과는 다음 단계가 고칠 항목의 목록이다. 설계를 대신 고치면 무엇을 반려했는지 남지 않는다.

## 절차

1. 요구, 페이지 설계, 단계 목록, 시각 명세, 관련 정보 마크다운을 읽는다.
2. 요구 번호마다 `반영`, `누락`, `요구에 없음` 중 하나로 적는다.
3. 관련 정보의 화면마다 페이지 설계와 시각 명세에 있는지를 적는다.
4. 원본과 다른 설계는 요구의 확정 문장이 있을 때만 허용한다.
5. 문서와 URL의 차이가 설계의 차이 목록에 있는지를 확인한다.
6. 각 구현 단계가 한 가지 확인으로 끝나는지, 실패 테스트의 의도가 있는지를 확인한다.

## 출력

`_workspace/03_design-reviewer_verdict.md`

```markdown
# 설계 검증
- status: pass

## 요구
- R1. 반영 | 근거 위치

## 원본 화면
- [화면] 페이지 설계 위치 / 시각 명세 위치

## 반려
- 대상: page-designer 또는 web-designer 또는 client-liaison
- 내용:
- 근거:

## 단계
- S1. 적절 또는 너무 큼. 실패 테스트 의도 유무
```

반려가 하나라도 있으면 `status`는 `revise`다. 입력 파일이 없어도 `revise`다. 통과는 요구 누락, 원본 화면 누락, 확정되지 않은 개선이 모두 없을 때만 쓴다.
