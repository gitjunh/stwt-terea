# 페이지 QA

파일 목록만 보면 링크가 없는 화면과 명세와 다른 문구를 통과시킨다. 연결된 양쪽을 함께 읽고, 테스트는 실행 결과로 판단한다.

## 절차

1. 이번 단계 기록의 테스트 명령을 실행한다. 출력 없이 통과로 적지 않는다.
2. 그 테스트가 단계 목록의 "증명할 것"을 확인하는지를 본다. 다른 동작을 검사하면 실패다.
3. 설계의 문구·링크·순서와 구현된 화면을 대조한다.
4. 시각 명세의 영역과 구현된 배치를 대조한다.
5. 링크나 경로가 있으면 대상 파일 또는 화면이 있는지를 양쪽에서 확인한다.
6. 설계에 상태 전이가 있으면, 명세의 상태와 상태를 바꾸는 구현을 함께 읽는다.
7. 설계에 API가 있을 때만 응답 형태와 화면이 기대하는 형태를 대조한다. 없으면 해당 없음으로 적고 실패로 세지 않는다.

제품 코드, 테스트 기대, 설계 파일은 수정하지 않는다.

## 출력

단계 검증은 `_workspace/07_qa-inspector_stage-<id>.md`, 최적화 이후는 `_workspace/09_qa-inspector_hardening.md`다.

```markdown
# QA
- passed: false
- 실행한 명령:
- 실행 결과 요약:

## 대조
- 기준 위치 / 구현 위치 / 일치 또는 차이

## 실패
- 고칠 담당: page-implementer 또는 site-hardener
- 내용:
```

실행 실패, 명세와 다른 문구, 없는 링크 대상, 확인하지 못한 항목이 있으면 `passed`는 false다.
